# envsec

Per-machine encrypted `.env` workflow using [sops](https://github.com/getsops/sops) + [age](https://age-encryption.org), as a single static Go binary. No other tools are required — sops and age are compiled in as Go libraries.

## Why

Whenever I set up a repo, I keep my API keys and other credentials in a `.env` file (or `.env.local`). I've always wondered: what if a malicious actor gains access to my system, or reads my files remotely, and I never know it? Suddenly all of those secrets are theirs to use. This utility prevents that by encrypting the files at rest.

- Secrets live in the repo as a **sealed dotenv file** (`FILE.enc.env`).
- Each machine has its **own age key**, so only authorized machines can decrypt.
- Nothing in the repo is machine-specific: the public key is derived from the local private key.
- **Offline.** No server, no SaaS, no vendor lock-in (age & sops are open standards; you can decrypt your files with the `age`/`sops` CLIs directly).

## Install

```sh
go install github.com/r3s/envsec@latest
```

For a release build (smaller static binary):

```sh
make release   # CGO_ENABLED=0 go build -trimpath -ldflags "-s -w"
```

## Commands

| Command | Purpose |
|---|---|
| `envsec init` | generate this machine's age key, print its public key |
| `envsec doctor` | show key status and embedded sops/age versions |
| `envsec seal [-f FILE] -- CMD...` | run your pull script, then (re)encrypt to `FILE.enc.env` |
| `envsec run [-f FILE] -- CMD...` | decrypt in memory, run CMD with secrets injected |
| `envsec edit [-f FILE]` | open sealed secrets in `$EDITOR`, re-encrypt on save |
| `envsec export [-f FILE]` | write decrypted secrets to `FILE` on disk (debug only) |
| `envsec addrecipient [-f FILE] PUBKEY...` | grant other machines access to `FILE.enc.env` |

`-f FILE` defaults to `.env.local`; the sealed file is always `FILE.enc.env`.

## The flow, step by step

### 1. Set up a machine (once per machine)

```sh
envsec init
```

This generates the machine's age key and prints its public key. Run `envsec doctor` any time to re-check the key and see the embedded sops/age versions. See [Age keys](#age-keys) for where the key lives.

### 2. Bootstrap the repo's secrets (first time, on your machine)

If you have a script that fetches the secrets from wherever the source of truth lives (password manager, upstream API, etc.), you can pass that command to `seal`:

```sh
envsec seal -- ./scripts/pull-secrets.sh
```

`seal` decrypts the current sealed file to a plaintext `.env.local` *before* running your pull script (so partial pulls can read the existing values), then re-encrypts the result atomically. The plaintext is removed on success, error, or Ctrl-C.

**Commit `FILE.enc.env`** — that is the only artifact that goes in the repo.

### 3. Give other machines access

Each machine has its own key, so you must explicitly admit the machines that may decrypt:

```sh
# on the new machine
envsec init                          # prints: This machine's PUBLIC key: age1...
# send that key to whoever owns the sealed file

# on a machine that already has access
envsec addrecipient age1mn2...       # grant the new machine access
```

Then commit the re-sealed file. The new machine pulls and can now `run`/`edit`. Recipients are **preserved** on every re-seal/edit/add, so nobody is ever silently locked out.

### 4. Daily use

```sh
envsec run -- npm run dev       # secrets injected into the environment, never written to disk
envsec edit                     # quick manual changes in $EDITOR
```

### 5. Refreshing secrets

```sh
envsec seal -- ./scripts/pull-secrets.sh   # re-run after the source changes
```

## Age keys

### Where the key lives

```
$SOPS_AGE_KEY_FILE                    # if set, used as-is
~/.config/sops/age/keys.txt           # default (same location the sops CLI uses)
```

`envsec init` creates the directory and the file, writes permissions `0600`, and prints the machine's public key.

Example `keys.txt` (generated by `envsec init` or `age-keygen`):

```
# created: 2026-10-19T11:51:44Z
# public key: age1psny8zyprl3ngzdjs8jlwmhd9spjpzqp4973kvm6yd59j09ha4qqcez76x
AGE-SECRET-KEY-1QTFSCEAQEM9DGPZ9D4UY...
```

- The `# public key:` line is a comment; `envsec doctor` derives it from the secret key line.
- Only native age identities (`AGE-SECRET-KEY-1...`) are supported — the format `envsec init` and `age-keygen` write.
- The same file works with the `age` and `sops` CLIs, so you can decrypt with either at any time.

### What to do with each part

| Part | Store | Notes |
|---|---|---|
| **Private key** (`keys.txt`) | Keep on the machine; back it up (e.g. password manager) | Without it the sealed files cannot be decrypted. Never commit it. |
| **Public key** (`age1...`) | Share freely, commit nowhere | It's the "recipient" written into sealed files, letting others encrypt *to* you. |

### Removing access

Remove the recipient by re-sealing to only the keys you want, or by using `sops updatekeys` on the file directly.

## Security properties

- `run` decrypts **in memory** and `exec(3)`s the command — secrets never touch disk.
- `seal`/`edit`/`export` write plaintext with mode `0600` and remove it on exit.
- Sealed output is written **atomically** (temp file + rename), so a crash can't corrupt the file.
- Recipients are **preserved** on every re-seal, edit, and add — access is never silently revoked.
- The envelope format is byte-identical to `sops encrypt/decrypt`, so files interoperate with the sops CLI.

## Requirements

- Go 1.27+ to build; the binary itself has no runtime dependencies.
- An age key (run `envsec init`).

## Layout

| File | Purpose |
|---|---|
| `main.go` | CLI dispatch + usage |
| `keys.go` | key file location, generation, public key derivation |
| `crypto.go` | sops library wiring (encrypt/decrypt), quote normalization, atomic writes |
| `flags.go` | `[-f FILE] -- CMD` parsing |
| `cmd_*.go` | one file per subcommand |
| `main_test.go` | unit + end-to-end tests (round trip, seal, edit, export, addrecipient, env injection) |

## Notes

- Two direct dependencies (`sops` v3, `age`) at their latest versions; everything else is stdlib.
